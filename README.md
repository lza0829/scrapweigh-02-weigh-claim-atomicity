## 过磅落条与秤位钉住（同票口径）

全局贯彻**同笔多写**：过磅入站时，秤位钉住、磅条行、毛/皮/净重量列、过磅审计在同一个
`BEGIN IMMEDIATE` 事务内同时成败。任一项失败 → 整笔回滚，回到过磅前快照（无条、无钉住、
无审计）。不存在「先钉后补磅条」的在途窗口，因此也没有超时解钉状态。

- 钉住见证：`scale_holds`（每秤至多一行，指向一条真实磅条）。`占用 ⇔ 有在途钉住`。
- 秤位谓词：`v_scale_gate.can_accept` 是唯一口径 —— 写侧 CAS 的 `WHERE`、读侧「可接新磅」
  都取自它，不另写判断。
- 对照面：`GET /api/过磅对照`（前端「过磅对照」页）并排给出秤位钉住 / 磅条 / 重量 / 审计，
  `v_weight_consistency` 只要出现「秤钉无条」「条在秤空」「占用无凭」即为脏写。
- 结价、销单在同一事务内解钉；同秤无后续未结磅条时秤位回空闲。

测试覆盖：同笔成功钉住并落条、落条途中失败整笔回滚、并发抢最后一杆空秤、回执成功态势同涨、
读侧谓词与写侧逐秤重放、半截脏写对照、结价/销单解钉、旧库回填。

```bash
cd backend && pytest -q
```
